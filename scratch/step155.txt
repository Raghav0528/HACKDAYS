## Existing Physics Features

Search across `src/coordination/conflictDetection.js`, `src/coordination/adaptiveIntervention.js`, `src/robots/robotMovement.js`, `src/main.js`, and `src/network/edgeClient.js`:

1. **`dynamic_interaction_radius_m`**:
   - *Status*: **Not implemented in codebase**.
   - *Existing foundation*: Config contains exact parameters: `r_min: 5.0, r_max: 20.0, tau_react: 1.5, beta_density: 1.0, density_radius: 8.0`.

2. **`nearest_robot_relative_speed_mps`**:
   - *Status*: **Not implemented in codebase**.
   - *Existing foundation*: Speeds are known via `robot.speed` (px/s) and `other.speed`.

3. **`nearest_robot_relative_heading_rad`**:
   - *Status*: **Not implemented in codebase**.
   - *Existing foundation*: Waypoint geometry exists; angles can be derived via `Math.atan2`.

4. **`closing_velocity_mps`**:
   - *Status*: **Not implemented in codebase**.
   - *Existing foundation*: Position vectors $\Delta\mathbf{p}$ and velocity vectors $\Delta\mathbf{v}$ are obtainable from robot coordinates and speeds.

5. **`true_ttc_sec`**:
   - *Status*: **Not implemented in codebase**.
   - *Existing foundation*: [conflictDetection.js](../src/coordination/conflictDetection.js) computes discrete waypoint time arrivals (`timeA`, `timeB`), but continuous vector Time-To-Collision ($\text{TTC}$) is not currently computed.

6. **`cpa_time_sec` & `cpa_distance_m`**:
   - *Status*: **Not implemented in codebase**.
   - *Existing foundation*: Neither Closest Point of Approach time nor distance is currently implemented in any JS or Python file.

7. **`intersection_conflict` (or `intersection_conflict_flag`)**:
   - *Status*: **Partially available via proxy**.
   - *Existing foundation*: [conflictDetection.js](../src/coordination/conflictDetection.js) has `classifyConflict()` which detects `CROSSING` vs `HEAD_ON` vs `SAME_DIRECTION`, and `c.type === 'vertex'`. This directly maps to $1$ for intersection crossing and $0$ otherwise.

## Required Integration Changes

### A. Python Backend (`server/predictor.py`)
- Change model and preprocessor paths from `amr_decision_model.pkl` / `amr_preprocessor.pkl` to `amr_ares_v2_model.pkl` / `amr_ares_v2_preprocessor.pkl`.
- Load `ml/amr_ares_v2_config.pkl` to retrieve `classes: ['MOVE', 'SLOW', 'WAIT', 'REROUTE']`.
- Update `FEATURE_COLUMNS` to the 26 V2 features.
- Update `DEFAULT_NUMERICAL` and `DEFAULT_CATEGORICAL` mappings.
- Map XGBoost numeric output `int(model.predict(X)[0])` $\in [0, 1, 2, 3]$ to label string `classes[pred_idx]`.

### B. Node Server (`server/index.js`)
- Ensure payload parsing correctly forwards the V2 feature dictionary to Python stdin. (Already supports arbitrary feature dictionaries).

### C. Frontend Feature Builder (`src/network/edgeClient.js`)
- Update `buildRobotFeatures()` to compute:
  - `heading_rad` using `Math.atan2(dy, dx)`.
  - `dynamic_interaction_radius_m` using the V2 config formula.
  - Nearest robot kinematics: `nearest_robot_relative_speed_mps`, `nearest_robot_relative_heading_rad`.
  - Continuous trajectory physics: `closing_velocity_mps`, `true_ttc_sec`, `cpa_time_sec`, `cpa_distance_m`.
  - Binary `intersection_conflict`: $1$ if crossing conflict detected, else $0$.
  - Categorical harmonization: map task `'DELIVER'` $\rightarrow$ `'DROP'`; map `'PERPENDICULAR'` $\rightarrow$ `'CROSSING'`.
